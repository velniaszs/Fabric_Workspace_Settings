One active policy set per capacity, enforced for every workspace sitting on it.
Rule 1
Deny all — Power BI only
Always present
Blocks every Fabric item type for every workspace on the capacity — Power BI items stay available. This is the rule that applies to non-OAP workspaces: they can keep creating reports, semantic models and dashboards, and nothing else. Power BI items stay open because the ItemCreation policy does not track them at all.

Fabric has no Deny effect, so the rule is written as an Allow that can never match. Its job is to keep the policy non-empty — a policy with no rules is not enforced, and the capacity would silently open.
workspace.id AnyOf [ 000…000 ] A sentinel GUID that matches no real workspace. Rule name: Deny all item creation (PBI items not tracked).
Rule 2
OAP workspaces — approved item types
OAP-enabled only
Lets OAP-enabled workspaces create a specific list of Fabric item types — lakehouses, warehouses, notebooks, pipelines and so on — on top of Power BI. Both conditions must hold: the workspace is OAP-enabled in the inventory and the item is on the approved list. The approved types are kept in a table, so adding one is a data change, not a code change.
workspace.id AnyOf [ OAP workspaces ]
AND
item.type AnyOf [ approved types ] Up to 49 workspaces per rule, so a large capacity carries several copies of rule 2.
Rule 3
Exceptions — allow all
Only when exceptions exist
Lets a short, owned list of workspaces create any item type at all. The missing item-type condition is the whole point: with nothing to narrow it, the rule matches every type. Because every rule is an Allow rule, an exception simply supersedes rule 2 — there is no precedence to implement.
workspace.id AnyOf [ excepted ] And nothing else — no item.type condition. Up to 49 workspaces per rule.

A capacity with no OAP workspace carries rule 1 alone. That is a correctly locked, Power BI-only capacity, not an error.
Every publish replaces the whole list. Rules are never edited one at a time, so hand edits made in the portal do not survive the next rebuild.
Rules cost against a ceiling of 50. 1 + ceil(OAP / 49) + ceil(exceptions / 49) — roughly 2,400 OAP workspaces per capacity.
Every rule is an Allow, and rules are ORed. A creation is permitted if any one rule matches it.
